# Security Policy

## Supported Versions

VecinoHub is in active development. Security fixes target `main`. Older tags are not maintained.

## Reporting a Vulnerability

Please **do not** open a public GitHub issue for security problems.

Email `calderaro94@gmail.com` with:

- A description of the issue and its impact.
- Steps to reproduce (a minimal proof of concept is ideal).
- Affected commit / branch.
- Optional: a suggested fix.

You should expect an acknowledgement within 72 hours and a status update within 7 days. Once a fix is ready, we coordinate disclosure timing with you.

## Out of Scope

- Reports generated by automated scanners without a working PoC.
- Self-XSS or attacks that require an already-compromised account.
- Vulnerabilities in third-party dependencies that have no exploitable path through VecinoHub — please report those upstream.

## Hardening Reminders for Deployers

- Set `BETTER_AUTH_SECRET` to a ≥32-character random string (`openssl rand -base64 48`).
- Set `BETTER_AUTH_URL` to the canonical production URL.
- Run behind HTTPS only. The app sets `secure` cookies when `NODE_ENV=production`.
- Configure SMTP credentials so password-reset and OTP emails actually deliver — auth flows fail closed when SMTP is missing.
- Better Auth's built-in rate limits are app-level. Add edge / WAF rate limiting (Vercel rate limit, Cloudflare, etc.) in front of the deployment.
- OAuth tokens are encrypted at rest (`encryptOAuthTokens: true`); rotate `BETTER_AUTH_SECRET` carefully — it is the encryption key.
